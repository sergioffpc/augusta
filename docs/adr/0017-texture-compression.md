# Texture Compression

Textures are baked to BC7/BC5/BC4 in KTX2 containers via Khronos' libktx
(KTX-Software), from vcpkg's `ktx` port.

The cooker encodes each texture to UASTC with libktx, then transcodes it, still
at cook time, to the BC format its `augusta:textureFormat` names: `bc7` to
`VK_FORMAT_BC7_SRGB_BLOCK` (colour), `bc5` to `VK_FORMAT_BC5_UNORM_BLOCK`
(normals) and `bc4` to `VK_FORMAT_BC4_UNORM_BLOCK` (single-channel data such as
masks and roughness); any other value is `bc7`. The levels are then
supercompressed with Zstandard and the KTX2 written. Fixed parameters: UASTC
quality level 2, no RDO, Zstandard level 18. Each texture carries its full mip
chain, generated by stb_image_resize2 with sRGB-correct filtering for `bc7`,
since libktx has no mip generation of its own.

The client is desktop Vulkan only (ADR-0059), and every desktop GPU samples BC,
so the pack holds the GPU format itself: the runtime never transcodes, it only
inflates the Zstandard levels. The client reads KTX2 with the same libktx,
linked only into the Renderer (the server packs no textures, ADR-0019), and
uploads the levels through NVRHI, not libktx's own Vulkan upload, which would
bypass NVRHI's resource state tracking.

Every KTX2 the cooker writes passes `ktx validate`, from vcpkg's `ktx[tools]`,
in the cooker's tests.

Source images (PNG/JPEG) are decoded by stb_image into 8-bit RGBA. stb_image is
the one decoder on Windows and Linux alike, so an image decodes to the same
pixels on either. It narrows 16-bit channels to 8 bits and ignores a PNG's
gamma, sRGB and colour-profile chunks - the pixels are taken as stored.

## Considered Options

- **BC encoded directly, by DirectXTex, in DDS containers**: the previous
  design. DDS is a Direct3D container, and DirectXTex a Microsoft library; on a
  Vulkan-only client, KTX2 is the standard container, carrying the `VkFormat`
  and its colour space, and Khronos' tools encode, validate and read it end to
  end. Encoding through UASTC loses a little against a direct BC7 encoder:
  UASTC-to-BC7 transcoding is near-lossless against UASTC, and UASTC is close
  to, though below, a good BC7 encoder.
- **UASTC in the pack, transcoded to BC at load**: what Basis Universal is for.
  It pays off for one file serving GPUs without BC (mobile ASTC), which this
  client has none of, and costs a transcode at every load plus libktx's
  transcoder in the runtime. Rejected.
- **The BC encode by bc7enc_rdo or Compressonator, libktx writing the
  container**: drops DirectXTex too, but keeps a second vendor's encoder beside
  libktx. Rejected.
- **The KTX2 written by hand**: the Data Format Descriptor is easy to get wrong
  and libktx writes it. Rejected.
- **Calling the `ktx create` CLI**: generates mips itself, but is a subprocess
  in a pipeline that has none (ADR-0030). Rejected.
- **ETC1S, and RDO on UASTC**: both shrink the pack at a cost in quality.
  Deferred until the pack's size matters.
- **A linear BC7** for non-colour data with more than two channels: deferred
  until a texture needs it.
