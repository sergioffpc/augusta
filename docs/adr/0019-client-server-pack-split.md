# Client/Server Pack Split

Client and server packs are baked from the same source in one cook run (issue #51): the client pack is full (geometry, textures, meshes, audio, plus collision geometry, spawn points, and hitboxes); the server pack is stripped down to collision geometry, spawn points, and hitboxes, omitting the mesh/texture/audio content the headless Linux server never needs, plus the scenario's Lua scripts (ADR-0031, ADR-0039), which only the server ever reads: a client is sent the values a script decides, never the script. The server pack also carries the hash of the client pack cooked with it (ADR-0031, ADR-0038), since a signature alone proves only that a pack came from the signing key, not that the two packs came from the same cook. Collision/spawn/hitbox data lands in both packs rather than server-only, since the client needs it too (client-side prediction, movement, and hit-detection against the same geometry the server uses).
