PROTOTYPE · THROWAWAY

Predicting your own player, and correcting it

The client moves its own player at once (Client-side prediction) and sends each tick's Command to the Authoritative server, which takes in one Command per tick, holds the last movement for 100 ms when none has arrived, and answers with its body and the newest Command it acknowledged. When that answer disagrees with what the client predicted after the same Command, the client restores the server's body and replays every Command the server has not yet acknowledged; the jump that makes is hidden by sliding the shown body for 47 ms (ADR-0004, ADR-0038). Does that keep the player responsive, and correct, under latency, loss, a clock that runs fast, and things only the server knows? Pick a walkthrough, or change a Parameter and scrub through the run.

What this prototype assumes that the specs do not fix
  • Seen from above, flat: a body is a 0.6 m square that slides along walls axis by axis. Walking is 3 m/s, sprinting 5.5 m/s, both reached at 30 m/s². Stamina drains at 0.35/s while sprinting, comes back at 0.2/s, and a body that runs out is exhausted, and walks, until it is back above 0.3. None of this is PhysX; only that the client and server step the same rules matters.
  • The tick rate is 60 Hz. The client's frames run at 120 Hz and show the newest Prediction State, not one interpolated between two.
  • Every message's latency is its link's one-way latency plus a uniform jitter; a message is lost on its own chance or inside a loss window. Nothing is quantized on a grid.
  • The client handles the newest Authoritative State update at the start of its next tick, before it predicts that tick's Command, as the Prediction thread does with what Network I/O published (ADR-0005).
  • "PhysX drift" adds a uniform random error of up to that many millimetres to the server's body after each tick, standing in for PhysX's lack of cross-platform determinism. A crate, a knock and a teleport are things the server does that the client's PredictionWorld cannot know.
  • "Blend" is the option ADR-0004 rejected: on a disagreement, move the body and every Command still held by a fraction of the error, with no replay.
